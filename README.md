# shrink

Unix-фільтр без стану: читає код або текст зі stdin, стискає його для контексту LLM і одразу віддає в stdout наступній програмі. Працює локально, без мережі й без виклику моделі.

```bash
files-to-prompt docs | shrink --level 3 --stats | llm "що тут головне?"
```

[![CI](https://github.com/Ki-mik0/Shrink/actions/workflows/ci.yml/badge.svg)](https://github.com/Ki-mik0/Shrink/actions/workflows/ci.yml)

> Статус: етапи 1, 2 (2a–2e) і 3a завершено. Є режими `auto` (типовий), `code` (Python), `json`, `log` і `text`, локальний переклад з будь-якої мови на англійську, стиснення під запит і бюджет токенів, точний офлайн-підрахунок і вартість, а також `shrink wrap` — проксі для агентів (Claude Code, Codex) зі звітом `shrink gain`; eval і реліз — далі, див. [docs/PLAN.md](docs/PLAN.md).

## Встановлення

```bash
python -m venv .venv
.venv/Scripts/activate        # Linux/macOS: source .venv/bin/activate
pip install -e ".[dev]"       # + інструменти розробки
pip install -e ".[tokens]"    # опційно: точний підрахунок токенів через tiktoken
shrink --download tokenizer   # один раз: словник o200k_base (~3,6 МБ) у кеш, далі все офлайн
pip install -e ".[translate]" # опційно: локальний переклад (ctranslate2, sentencepiece, fasttext)
shrink --download translate   # один раз: модель NLLB-200 (~630 МБ) і визначник мови
```

Глобальна команда (коли буде потрібна): `pipx install .`

## Використання

```bash
cat notes.md | shrink                    # режим auto, рівень 2
cat app.py | shrink -l 3                 # скелет: сигнатури без тіл
cat notes.md | shrink -l 3 --stats       # максимальне стиснення + статистика в stderr
shrink --list-modes                      # доступні режими
shrink --mode-help text                  # що саме робить режим на кожному рівні
```

| Прапорець | Що робить |
| --- | --- |
| `-m, --mode` | `auto` (типовий: сам вибирає `code`, `web`, `json`, `log` або `text` для кожного файлу), `code`, `web`, `json`, `log`, `text`; кілька режимів через кому (`a,b`) виконуються по черзі |
| `-l, --level` | 1 — легкий, 2 — середній (типовий), 3 — лише структура |
| `--format` | формат упакованого входу: `auto` (типово), `none`, `files-to-prompt`, `cxml`, `repomix-xml`, `repomix-markdown`, `repomix-plain` |
| `--delimiter REGEX` | новий файл починається з кожного рядка, що збігається з REGEX (іменована група `path` = ім'я файлу); перекриває `--format` |
| `--diff` | unified diff кожного файлу в stderr (без префікса, тож `2> changes.diff` дає придатний файл), а потім звіт `--stats`; рамка файлів у diff не потрапляє |
| `--stats[=json]` | токени до/після і відсоток у stderr (разом із рамкою файлів) та рядок на кожен крок: скільки зекономив кожен метод; `--stats=json` — один JSON-об'єкт; без словника — оцінка «символи / 4», позначена `~`, і підказка, як отримати точні числа |
| `--encoding` | токенізатор для підрахунку: `o200k_base` (типовий) або `cl100k_base` |
| `--price USD[/CACHED]` | ціна вхідних токенів за мільйон (і, через `/`, кешованих) — у звіті з'являється вартість виклику до/після |
| `--cache-hit RATE` | частка вхідних токенів, що читаються з кешу промптів (0–1), разом із `--price` |
| `--translate` | після режиму перекласти прозу з будь-якої мови на англійську локальною моделлю, там де це дешевше в токенах |
| `--translate-from LANGS` | перекладати лише ці мови, напр. `uk,ru` |
| `-q, --query TEXT` | лишити цілим те, що відповідає запиту (BM25 по функціях і абзацах), а решту стиснути рівнем `--level` |
| `--budget TOKENS` | стискати найменш релевантні файли сильніше, доки вивід не вміститься в бюджет; текст ніколи не обрізається |
| `--no-docs` | після режиму прибрати й докстрінги Python та JSDoc (імена, параметри й типи лишаються); з `--level 3` лишаються самі сигнатури. Не входить у рівні, бо викидає прозу, яка може бути важливою; вмикається лише явно. Для генерації коду не рекомендований: в eval повнота впала з 97% до 67% |
| `--brief` | дописати після виводу коротку вказівку моделі відповідати стисло (без коментарів і докстрінгів у коді, без пояснень навколо, кожен файл один раз); економить вихідні токени, коштує ~65 вхідних |
| `--download tokenizer\|translate` | один раз завантажити словник токенізатора або модель перекладу й вийти; звичайний запуск мережу не чіпає ніколи |
| `--debug` | трейсбек при внутрішній помилці |
| `-V, --version`, `-h, --help` | версія, довідка |

### Режим `code` (Python)

| Рівень | Що прибирає |
| --- | --- |
| 1 | коментарі (shebang, рядок кодування й прагми `# type: ignore`, `# noqa`, `# pragma` лишаються), пробіли в кінці рядків, зайві порожні рядки; рядкові літерали не чіпаються |
| 2 | + докстрінги скорочуються до першого речення |
| 3 | + тіла функцій → `...`; лишаються сигнатури, типи, декоратори, однорядковий докстрінг, класи, імпорти й код модуля |

Кожен рівень перевіряється: результат знову розбирається `ast`, і дерево порівнюється з вхідним (на рівнях 1–2 код має бути той самий, на рівні 3 — усе поза тілами функцій). Якщо перевірка не пройшла або файл не розбирається, він іде без змін із попередженням у stderr. Правки робляться за позиціями в оригінальному тексті, тож форматування, кирилиця, CRLF і BOM зберігаються.

Оцінка на файлах stdlib (символи / 4):

| Файл | Рівень 1 | Рівень 2 | Рівень 3 |
| --- | --- | --- | --- |
| `argparse.py` | −17% | −26% | −86% |
| `dataclasses.py` | −44% | −50% | −89% |

### Режим `web` (JavaScript, CSS, HTML)

| Рівень | Що прибирає |
| --- | --- |
| 1 | коментарі JS (ліцензії `/*! */`, `// @ts-...`, прагми eslint, prettier, webpack і JSDoc лишаються), коментарі CSS і HTML (`<!--[if ...]>` лишається), пробіли в кінці, зайві порожні рядки |
| 2 | + JSDoc скорочується до першого речення (теги `@param`/`@returns` ідуть); CSS мініфікується: одне правило на рядок, без пробілів навколо `{ } ; , :` і без останньої `;` |
| 3 | + тіла `function` і стрілкових функцій з блоком → `{/* ... */}` (лишаються імена, параметри, значення за замовчуванням; позначка потрібна, бо голе `{}` модель читає як порожню реалізацію); у CSS лишаються селектори та змінні `--name: value` |

JavaScript розбирається власним лексером: рядки, шаблони з вкладеними `${...}`, регулярні вирази (відрізняються від ділення за попереднім токеном) і коментарі, тож `//` у рядку чи URL ніколи не вважається коментарем. Після рівнів 1–2 результат лекситься знову й мусить мати ті самі токени коду з переносами рядків там, де вони були (JavaScript сам ставить `;` на деяких переносах: `return /*\n*/ x` лишається `return\n x`). У HTML `<pre>` і `<textarea>` не чіпаються, а вбудовані `<script>` і `<style>` стискаються тими самими правилами. Файл, що не пройшов перевірку, іде без змін.

На фронтенді стартового проєкту з eval (4 файли, 3013 токенів): рівень 1 −11,7%, рівень 2 −31%, рівень 3 −70,5%; `node --check` проходить на кожному рівні.

### Режим `log`

| Рівень | Що прибирає |
| --- | --- |
| 1 | ANSI-коди кольорів і курсора, проміжні стани прогрес-барів (`\r`), пробіли в кінці, зайві порожні рядки; однакові сусідні рядки → один рядок із `[xN]` |
| 2 | + часові мітки на початку рядка (ISO 8601, `hh:mm:ss`, syslog), повтори блоків із 2–8 рядків → один блок і `[previous N lines xM]` |
| 3 | + рядки рівнів DEBUG, TRACE, VERBOSE, INFO → `[N lines dropped]` |

Кожне злиття чи маркер застосовується, лише якщо так коротше: `a [x2]` довше за два рядки `a`, тож вони лишаються.

### Режим `json`

| Рівень | Що робить |
| --- | --- |
| 1 | мініфікація; `\uXXXX` → самі символи; числа, порядок і дублікати ключів зберігаються точно (числа не проходять через float) |
| 2 | + масиви довші за 8 елементів → перші 5 і `"... +N more items"`; рядки довші за 300 символів → 200 і `"... (+N chars)"` |
| 3 | + масиви → перший елемент і лічильник, рядки довші за 60 → 40: лишається форма даних |

Вихід завжди валідний JSON. JSON Lines (по значенню в рядку) обробляється порядково. Обрізання масиву, яке вийшло б довшим, пропускається.

### Режим `text`

| Рівень | Що прибирає |
| --- | --- |
| 1 | пробіли в кінці рядків, зайві порожні рядки |
| 2 | + повтори пробілів усередині рядка (відступи лишаються), дублікати абзаців від 20 символів (заголовки не чіпаються) |
| 3 | + HTML-коментарі й теги, Markdown-посилання й зображення → їхній текст, горизонтальні лінії |

Fenced-блоки коду (```` ``` ````, `~~~`) на рівнях 2–3 не змінюються, inline-код на рівні 3 теж. Чистий CRLF-вхід лишається CRLF.

Приклад на [tests/fixtures/messy.md](tests/fixtures/messy.md) (текст, скопійований з HTML-документації):

| Рівень | Токени (оцінка) | Економія |
| --- | --- | --- |
| 1 | ~176 → ~175 | −0,6% |
| 2 | ~176 → ~131 | −25,6% |
| 3 | ~176 → ~69 | −60,8% |

На вже охайному Markdown (наприклад, документ плану) економія мала: −2,6% на рівні 3.

### Для агентів: `shrink wrap` і `shrink gain`

```bash
shrink wrap claude                  # Claude Code через локальний проксі shrink
shrink wrap --translate claude      # і ваші українські промпти — англійською
shrink wrap codex                   # OpenAI Codex CLI
shrink wrap --port 8787             # лише проксі: ANTHROPIC_BASE_URL=http://127.0.0.1:8787
shrink gain                         # скільки зекономлено за всі сесії
```

`shrink wrap` запускає на `127.0.0.1` проксі без сторонніх залежностей і стартує агента зі змінною `ANTHROPIC_BASE_URL` (для Codex — `OPENAI_BASE_URL=.../v1`), що вказує на нього. Кожен запит іде на справжній API з тим самим шляхом і заголовками (`anthropic-*`, `authorization`, `x-api-key`), тож працюють і API-ключі, і вхід через підписку. Відповіді передаються шматками в міру надходження: SSE-події, зокрема `ping`, доходять до агента без затримки, а статуси й тіла помилок не змінюються.

Що змінюється в запиті:

- вивід інструментів (`tool_result`, `function_call_output`, повідомлення `tool`): режим `log` (ANSI-коди, прогрес-бари, повтори) або мініфікація `json`, рівень `--level` (типово 1);
- з `--translate` — текст, який пише користувач.

Що не змінюється ніколи: `system`, визначення інструментів, `cache_control`, блоки thinking, попередні відповіді асистента, а також результати інструментів, що читають чи редагують файли (Read, Edit, Write, `read_file`…): агент редагує файл, цитуючи побачене, і скорочена копія зламала б заміну. Якщо в запиті нічого не скоротилося, пересилаються оригінальні байти. Стиснення детерміноване й кешується за вмістом, тож попередні ходи розмови щоразу виходять однаковими й кеш промптів провайдера не ламається.

`shrink gain` читає журнал (лише числа, без тексту й заголовків) у `%LOCALAPPDATA%\shrink\state` (або `~/.local/state/shrink`; `SHRINK_STATE_DIR` змінює місце): запити, токени до/після, економія за днями й агентами, `--json`, `--reset`. Розмова пересилається щоходу повністю, тож економія рахується на кожен запит, а кешовані токени провайдер рахує дешевше.

Перевірено з Claude Code (вхід через підписку Pro): `/status` показує `Anthropic base URL: http://127.0.0.1:<port>`. Із будь-яким нестандартним `ANTHROPIC_BASE_URL` Claude Code сам не завантажує керовані налаштування (`Managed settings`) і політику організації — це його поведінка, а не shrink; для особистого акаунта там зазвичай нічого немає.

Обмеження: частина версій Codex CLI ігнорує `OPENAI_BASE_URL` — тоді додайте провайдера з `base_url = "http://127.0.0.1:<port>/v1"` у `~/.codex/config.toml` і запустіть `shrink wrap --port <port>`. Gemini CLI поки не підтримується (його змінна для базового URL недокументована й ігнорується при вході через Google). На Windows проксі займає порт ексклюзивно, щоб інша програма не могла слухати той самий порт.

### Переклад з будь-якої мови на англійську

Токенізатори вчилися переважно на англійському тексті, тож те саме речення іншою мовою коштує більше токенів. `--translate` перекладає прозу локальною моделлю [NLLB-200](https://huggingface.co/facebook/nllb-200-distilled-600M) (600M, int8, CPU через CTranslate2), а мову кожного абзацу визначає fastText `lid.176`.

```bash
pip install -e ".[translate]"
shrink --download translate                   # один раз, ~630 МБ, файли перевіряються за SHA-256
cat notes_uk.md | shrink --translate --stats
```

Правила, щоб переклад нічого не зламав:

- перекладаються лише заголовки, пункти списків і абзаци прози; блоки коду, таблиці, HTML і файли з кодом чи JSON не чіпаються;
- inline-код, URL, e-mail, шляхи, прапорці й ідентифікатори (`user_id`, `getName()`) замінюються маркерами `__N__`, а після перекладу повертаються на місце. Маркери на кшталт `⟦0⟧` модель ламала, тому формат вибрано за заміром;
- англійські абзаци моделі не передаються;
- переклад приймається, лише якщо всі маркери повернулися рівно по разу, цифри збіглися, модель не видала невідомого токена й токенів стало менше. Інакше лишається оригінал.

На українському `docs/PLAN.md` (переважно таблиці, які поки не перекладаються) це дало 4950 → 4439 токенів (−10,3%) за ~17 с на CPU; на звичайній прозі з кодом і посиланнями — −25%. Модель робить смислові огріхи («пакет» → «packet»), тому якість перекладу окремо оцінюється на етапі eval. Ваги NLLB мають ліцензію CC-BY-NC-4.0 (некомерційне використання).

### Стиснення під запит і бюджет токенів

```bash
files-to-prompt src | shrink -l 3 --query "token counting tiktoken" --stats
files-to-prompt src | shrink --query "token counting" --budget 3000
```

`--query` ділить вхід на фрагменти — кожна функція й метод Python, кожен абзац решти тексту — і ранжує їх BM25 (ідентифікатори розбиваються на слова: `getUserName` → get, user, name; запит може бути будь-якою мовою). Фрагменти з оцінкою від половини найкращої вважаються релевантними:

- релевантні функції лишаються з тілом навіть на рівні 3, решта файлу стає скелетом;
- інші файли з релевантним абзацом стискаються легко (рівень 1);
- усе інше — рівнем `--level`.

`--budget N` після цього, поки вивід більший за N токенів, на один крок посилює стиснення найменш релевантного файлу (без запиту — найбільшого): підвищує рівень до 3, і лише потім забирає тіла збереженим функціям. Текст ніколи не обрізається: якщо навіть найсильніше стиснення не вкладається, у stderr буде попередження з досягнутим числом.

На чотирьох модулях самого shrink (6509 токенів) запит «token counting tiktoken» на рівні 3 лишив цілими 8 функцій підрахунку з `stats.py`, а решту звів до скелета: 2865 токенів (−56%). З `--budget 5000` вийшло 4864 токени за 4 кроки.

Обидва прапорці читають увесь вхід, перш ніж писати (ранжуванню й бюджету потрібні всі файли); без них shrink і далі обробляє потік по одному файлу.

### Точні токени й вартість

```bash
pip install -e ".[tokens]"
shrink --download tokenizer            # один раз, ~3,6 МБ у %LOCALAPPDATA%\shrink (або ~/.cache/shrink)
shrink -l 3 --stats --price 3/0.3 --cache-hit 0.5 < argparse.py > skeleton.py
```

```text
shrink: stats: 1 document, tokens 20240 -> 2867 (-85.8%) [o200k_base]
shrink:   comments    20240 -> 16709 (-17.4%, -17.4% of input)
shrink:   docstrings  16709 -> 14997 (-10.2%, -8.5% of input)
shrink:   bodies      14997 -> 2867 (-80.9%, -59.9% of input)
shrink: cost: $0.0334 -> $0.004731 per call, saves $0.0287 ($28.67 per 1000 calls) at $3/Mtok, cached $0.3/Mtok, 50% cache hits
```

Словник лежить у кеші shrink, а не в системній temp-теці, яку ОС може очистити; `SHRINK_CACHE_DIR` змінює місце. Ціни моделей shrink не зашиває (вони змінюються) — їх передають прапорцем. `o200k_base` — токенізатор GPT-4o і новіших моделей OpenAI; для Claude та інших це наближення.

### Скільки зекономлено і чим

```text
$ cat notes.md | shrink -l 3 --stats > /dev/null
shrink: stats: 1 document, tokens ~7 -> ~3 (-57.1%) [approx]
shrink:   whitespace         ~7 -> ~7 (+0.0%, +0.0% of input)
shrink:   spaces+duplicates  ~7 -> ~6 (-14.3%, -14.3% of input)
shrink:   markup             ~6 -> ~3 (-50.0%, -42.9% of input)
```

Рівні режиму `text` накопичувальні, тому кожен рядок показує внесок одного кроку: токени на вході й виході кроку, зміну в ньому та частку від усього входу. Підсумок по всіх файлах потоку сумується.

### Упакований вхід (files-to-prompt, Repomix)

Якщо на вході кілька файлів, shrink розпізнає формат за першими рядками, стискає **вміст кожного файлу окремо**, а рамку (заголовок із шляхом, `---`, `</file>`, преамбулу й епілог) повертає байт у байт. Без стиснення розбиття й склеювання відтворюють вхід точно, для будь-якого тексту (це перевіряють property-тести). Якщо формат не розпізнано, вхід лишається одним документом.

```bash
files-to-prompt src | shrink --level 2
files-to-prompt --cxml src | shrink
repomix --stdout | shrink --stats
```

Файли з розширенням коду (`.py`, `.js`, `.json`, …) у режимі `text` отримують лише рівень 1: вищі рівні прибирають «повторювані абзаци» й теги, а це змінює зміст коду. Режим `auto` (типовий) віддає Python-файли в `code`, а решту — в `text`.

### Поведінка в пайпі

| Ситуація | Результат | Код виходу |
| --- | --- | --- |
| успіх, порожній вхід | вихід у stdout | 0 |
| отримувач закрив пайп (`\| head`) | тихий вихід | 0 |
| файл не вдалося стиснути | файл без змін + попередження в stderr | 0 |
| внутрішня помилка | один рядок у stderr (трейсбек — з `--debug`) | 1 |
| неправильний прапорець | повідомлення Click | 2 |
| Ctrl+C | без трейсбеку | 130 |

Вхід читається як байти й декодується UTF-8 з `surrogateescape`, тож невалідні байти проходять без втрат. Однаковий вхід дає байт-у-байт однаковий вихід.

## Оцінювання

[eval/](eval/README.md): бенчмарк стиснення проти Repomix і skim на одному корпусі (shrink L3: −77% токенів, усі 33 Python-файли лишаються валідними; skim `structure`: −68,5%; Repomix `--compress`: −46%, 0/33 валідних) і eval якості відповідей моделі на стиснутому контексті через безкоштовні моделі OpenRouter: рівні 1–2 дають −9…−33% токенів без втрати точності (100%), рівень 3 — −76% при 85% (усі питання про структуру — 100%, втрачаються деталі з тіл функцій), рівень 3 з `--query` — −46% при 100% на прогнаних корпусах; хибних відповідей модель не вигадувала, лише «unknown». Переклад по 10 мовах: українська −32% токенів, польська −29%, японська −24%, російська −3% (o200k кодує її майже як англійську). Час старту на Windows: +147 мс понад інтерпретатор (`python -m shrink`). На великій задачі (todo-застосунок з авторизацією у змішаному проєкті FastAPI + JS, відповідь ~9 тис. токенів) рівень 3 зменшив вхід на 37,5% і весь запит на 23% без втрати повноти відповіді; з режимом `web` і `--brief` рівень 3 дає −55% входу і −36,8% усього запиту (середнє за 3 прогонами, повнота 97%, жодної обрізаної відповіді).

### Час старту (NFR-1)

Базовий замір, Windows 11, Python 3.12, медіана з 15–20 запусків:

| Команда | Час |
| --- | --- |
| `python -c pass` | ~110 мс |
| `python -c "import argparse"` | ~144 мс |
| `python -c "import click"` | ~228 мс |
| `python -m shrink -V` | ~273 мс |
| `shrink.exe -V` | ~310–340 мс |

На цій машині сам інтерпретатор із лаунчером `shrink.exe` займає ~175 мс, тому ціль 150 мс на Windows недосяжна з будь-яким фреймворком; Click додає ще ~118 мс. На Linux замір робить job `startup` у CI (hyperfine).
