# План розвитку shrink

Оновлено 2026-11-19. Етап 1 (CLI-ядро, режим `text`, `--stats`) завершено; цей документ описує етапи 2–4 до дедлайну 2027-05-30.

## 1. Що таке shrink і чого він хоче

shrink — локальний інструмент, що поєднує **кілька методів економії токенів** і в кінці показує, **скільки зекономлено** (загалом і по кожному методу): переклад **з будь-якої мови на англійську**, скелетизація коду, RAG-відбір релевантного, дедуплікація, стиснення логів і JSON.

Два способи використання:

1. **Фільтр** (ТЗ): `cat x | shrink | claude -p "…"`; `shrink --diff` показує в stderr, що прибрано, і таблицю «метод → токени до/після/%».
2. **Обгортка для агентів** (розширення, етап 3): `shrink wrap claude|codex|gemini` запускає агента через локальний проксі, який стискає кожен запит; `shrink gain` показує накопичену економію.

**Висновок.** Кожен конкурент закриває свій шматок. Не знайдено інструмента, який одночасно: (а) перекладає на англійську **з будь-якої мови** (неанглійський текст коштує більше токенів: для української ~1,5–2,4× відносно англійської в o200k, див. [arXiv 2601.13328](https://www.arxiv.org/pdf/2601.13328); для кожної мови множник свій і його треба міряти), (б) гарантує синтаксичну валідність скелета, (в) має детермінований вивід для кешування промптів, (г) показує економію по кожному методу.

**Що запозичуємо:** запобіжник «вивід ≤ входу» і бюджет токенів зі skim; «tee» сирого виводу при помилці з rtk; оборотність і проксі-обгортку з Headroom; методику eval (кілька прогонів, сліпе порівняння) з Ponytail; ідею query-aware відбору з LongCodeZip/LLMLingua.

## 3. Архітектура методів

Конвеєр (`src/shrink/pipeline.py`) лишається, а компресор стає **ланцюжком методів**. Кожен метод — стратегія з реєстру (`compressors/registry.py`) і повертає `Document` разом зі своєю статистикою «до/після».

| Метод | Що робить | Залежності |
| --- | --- | --- |
| `whitespace` / `dedup` | наявний `text`: пробіли, дублікати абзаців і рядків (`рядок ×N`) | stdlib |
| `skeleton` | код → сигнатури (назва, параметри, анотації, тип повернення, перший рядок докстрінга), тіла → `...`. Python: `ast` + правки за байтовими зміщеннями; JS/TS: Tree-sitter | stdlib / extra `[code]` |
| `comments` | коментарі й докстрінги через `tokenize`; прагми та shebang зберігаються | stdlib |
| `log` | ANSI, часові мітки, повтори, однакові кадри стектрейсів | stdlib |
| `json` | мініфікація з `ensure_ascii=False`, обрізання довгих масивів із позначкою | stdlib |
| `translate` | будь-яка мова → англійська (автовизначення мови) | extra `[translate]` |
| `rag` (`--query`) | BM25 по чанках (функція, клас, абзац): релевантні лишаються повністю, решта — скелетом | stdlib |
| `budget` (`--budget N`) | каскадом вмикає сильніші методи, доки результат не вміститься в N токенів | — |

- `--mode auto|code|text|log|json` визначає тип вмісту за розширенням зі splitter або за вмістом; `--level 1–3` — пресет методів; `--translate`, `--query`, `--budget`, `--methods a,b,c` — явний контроль.
- **Звіт економії:** `--stats` — рядок у stderr; `--stats=json` — машиночитний; `--diff` — unified diff і таблиця «метод → токени до/після/%». Підрахунок — tiktoken (o200k_base), без нього оцінка з позначкою `~`. Вартість у доларах враховує ціну кешованих токенів.
- **Переклад any→en** (`compressors/translate.py`, `compressors/langdetect.py`):
  - **Визначення мови** по кожному прозовому сегменту окремо (текст може бути змішаним: український коментар у російській документації тощо). Швидка перевірка за Unicode-скриптом відсіює латиницю та код; для решти — офлайн-детектор (кандидат: `lingua-py`, без мережі). Англійські сегменти не чіпаються.
  - **Модель** — одна багатомовна seq2seq-модель у форматі CTranslate2, CPU, int8. Кандидати для порівняння на етапі 2d: NLLB-200 distilled 600M (200 мов; ваги під CC-BY-NC, що для курсової прийнятно, але блокує комерційне використання), M2M100 (MIT), `opus-mt-mul-en` (легша, слабша якість), MADLAD-400 (Apache-2.0, важка). Вибір за якістю й токенами в eval; ліцензію моделі фіксуємо в README. Парні моделі opus-mt (`uk-en`, `ru-en` тощо) — необов'язковий швидкий шлях для найчастіших мов.
  - **Завантаження** лише командою `shrink models download translate`; жодних автоматичних мережевих запитів. `shrink models list` показує, що встановлено.
  - **Захист**: код, inline-код, ідентифікатори, URL, числа й шляхи замінюються плейсхолдерами й повертаються на місце після перекладу.
  - **Правило прийняття**: сегмент замінюється перекладом, лише якщо токенів стало менше. Для мов, що вже токенізуються ефективно, переклад відхиляється автоматично, тож економія завжди виміряна, а не гіпотетична.
  - **Детермінованість**: greedy-декодування, фіксована модель. Кеш перекладів за хешем сегмента (локальний файл) прискорює повтори.
  - Керування: `--translate[=auto|<код мови>]`, `--translate-from uk,ru` (обмежити мови), `--reply-lang <код>` додає коротку інструкцію «відповідай мовою користувача».
- **Обгортка `shrink wrap <агент>`** (`integrations/wrap.py`, `proxy.py`): локальний HTTP-проксі на `127.0.0.1`, підключається через `ANTHROPIC_BASE_URL` / `OPENAI_BASE_URL` / змінну Gemini. Стискає текст користувача й вміст `tool_result`. Правила: не чіпати `tool_use_id`, назви й аргументи інструментів; **не змінювати вже надісланий префікс розмови** (інакше зламається кешування промптів); результати стиснення кешувати за хешем; fail-open. Статистика — `~/.shrink/gain.jsonl`, підсумок — `shrink gain`. Це єдине місце зі станом; воно винесене за межі ядра фільтра.

## 4. Best practices (чекліст)

- **Unix-фільтр** ([clig.dev](https://clig.dev/), Simon Willison): у stdout лише корисне навантаження, діагностика в stderr; `-q`; `NO_COLOR`; коди 0/1/2/130; атомарний запис. Здебільшого вже є в `cli.py` та `io/`.
- **Межі програми:** EPIPE (є `silence_stdout`); на POSIX після SIGINT процес перепосилає сигнал собі; зняття BOM; NUL у перших 8 КБ → бінарний вхід іде без змін; ліміт `--max-bytes`.
- **Код:** правки за байтовими зміщеннями, а не `ast.unparse` (`col_offset` в `ast` — байтові зміщення UTF-8); повторний розбір як валідація; інваріант «текст до `body.start_byte` не змінюється»; запобіжник «вивід ≤ входу»; fail-open.
- **Текст:** прибирати форматування, а не слова ([arXiv 2508.13666](https://arxiv.org/html/2508.13666v1), [2502.15007](https://arxiv.org/abs/2502.15007), [2407.08892](https://arxiv.org/abs/2407.08892)); відступи Python/YAML/fenced-коду не чіпати; стоп-слова лише через явний `--aggressive`.
- **Токени:** вкладений `o200k_base.tiktoken` з `expected_hash` (tiktoken за замовчуванням тягне словник із мережі), `encode_ordinary`, назва енкодингу в звіті.
- **Агенти:** `SHRINK_PASSTHROUGH=1`; сирий вивід у файл при ненульовому коді; `--diff` як прозорість.
- **Інженерія:** детермінованість; ліниві імпорти + import-linter (ядро не тягне tiktoken, tree-sitter, ctranslate2); pre-commit; CHANGELOG/SemVer; Dependabot; Trusted Publishing.

## 5. Рішення

- Назва на PyPI — **`llm-shrink`** (`shrink` зайнята, `llm-shrink` перевірено 2026-11-19 як вільна); команда лишається `shrink`. Extras: `[tokens]`, `[code]`, `[translate]`, `[all]`.
- Python ≥ 3.10 лишається за ТЗ (NFR-8); у CI-матриці додано 3.14.
- NFR-1 переходить на відносну метрику «≤ X мс понад `python -c pass`»; X погодити з керівником.
- Обгортку й переклад погодити з керівником як розширення ТЗ.

## 7. Ризики

| Ризик | Як знизити |
| --- | --- |
| Розростання обсягу | пріоритет: фільтр + skeleton + translate + звіт; далі wrap; JS/TS останнім |
| Переклад псує зміст; якість різна для різних мов | eval по мовах; сегмент приймається лише коли токенів стало менше; можна вимкнути або обмежити мови |
| Ліцензія моделі перекладу (NLLB — CC-BY-NC) і розмір (0,6–3 ГБ) | модель опційна й завантажується явно; кандидати з вільною ліцензією в порівнянні; ліцензія в README |
| Проксі ламає кешування промптів або формат API | префікс не змінюється, fail-open, контрактні тести на мок-сервері |
